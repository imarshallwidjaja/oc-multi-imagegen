# Unit test instructions

- Keep unit tests independent of real credentials and provider access. OpenCode 1 `execute` tests use synthetic `OPENCODE_AUTH_CONTENT`; OpenCode 2 tests use the fake plugin context in `hosts.ts`, whose connection store answers per integration id; direct `backend.generate` tests pass fake credentials explicitly. All stub `globalThis.fetch`.
- Put behavior both hosts and both backends share in `imagegen.test.ts`, which runs each case against both adapters with each backend selected, through `hosts.ts`. Put host-specific behavior (permission request shape, credential handling, native sign-in registration, result shape, registration) in `v1.test.ts` or `v2.test.ts`, and each backend's exact request, arguments and limits in `codex.test.ts` or `openai-api.test.ts`; do not repeat shared cases there.
- Restore `OPENCODE_AUTH_CONTENT` and `globalThis.fetch` after tests that change them; test files share a Bun process.
- For auth-file tests, follow `auth.test.ts`'s temporary path and `mock.module("xdg-basedir", ...)`. `xdg-basedir` caches `XDG_DATA_HOME` at first import, so changing that environment variable later does not redirect auth reads.
- `container.test.ts` runs `scripts/` as subprocesses against synthetic auth files and dotenv files in temporary directories and a fake `docker` on `PATH`. The fake `docker` never runs the script a container would, so the in-container probes (`container-skill-probe.sh`, `container-backend-probe.sh`) are run directly with a fake `opencode` and `wget`. It needs Bash, POSIX `sh`, GNU `timeout`, `base64` and Bun, and never real Docker, credentials or paid calls. Keep each safeguard (sandbox checks, seed refusal, container stop and unconfirmed stop, seed ownership, stale-work refusal, the probes' failure cases) tested there once.
- `index.test.ts` packs the repository with `npm pack`, extracts the tarball with `tar`, and uses `Bun.build` to bundle the entry point into the extracted copy, to resolve the skill the way an installed package does. It needs both commands on `PATH` and no earlier `bun run build`, network or credentials.
