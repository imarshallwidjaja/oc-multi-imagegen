# Unit test instructions

- Keep unit tests independent of real credentials and provider access. OpenCode 1 `execute` tests use synthetic `OPENCODE_AUTH_CONTENT`; OpenCode 2 tests use the fake plugin context in `hosts.ts`, whose connection store answers per integration id, where `active` returns only the saved connection and an environment key is resolved by name; direct image-tool tests pass fake credentials explicitly. All stub `globalThis.fetch`.
- Put behavior both hosts and the selected backends share in `imagegen.test.ts`, which runs each case against both adapters with each of the Codex, OpenAI Images API and NanoGPT backends selected, through `hosts.ts`; that includes which source the image API key comes from. Put host-specific behavior (permission and `webfetch` request shape, how a credential is looked up, native sign-in registration, result shape including preview attachment, namespaces and registration) in `v1.test.ts` or `v2.test.ts`, backend and option selection in `backend.test.ts`, and each backend's exact request, arguments and limits in `codex.test.ts`, `openai-api.test.ts`, `nano-gpt.test.ts` or `opencode.test.ts` (OpenCode 2 only, with the fake host's `generateImage` and `imageModels`); do not repeat shared cases there. Reference loading and URL downloads belong in `input-image.test.ts`, URL validation in `http-download.test.ts`, and alpha reports, the transparency warning and preview limits in `output-image.test.ts` and `png-alpha.test.ts`.
- Select a backend for shared cases with `selectBackendVariable` in `hosts.ts`. Exercise OpenCode 2 plugin options (`pluginOptions` in `createV2Context`) only where option handling is the behavior under test. Call `isolateEnvironment()` from `fixtures.ts` in every file that loads the plugin or reads a credential: test files share a Bun process, and it sets aside, unsets and restores `OPENCODE_AUTH_CONTENT`, `OC_MULTI_IMAGEGEN_BACKEND`, `OC_MULTI_IMAGEGEN_OPENAI_API_KEY` and `OC_MULTI_IMAGEGEN_NANOGPT_API_KEY` without printing or exposing inherited values. Restore `globalThis.fetch` after tests that change it.
- For auth-file tests, follow `auth.test.ts`'s temporary path and `mock.module("xdg-basedir", ...)`. `xdg-basedir` caches `XDG_DATA_HOME` at first import, so changing that environment variable later does not redirect auth reads.
- Key-source tests use distinct synthetic keys for the variable and the saved credential, so a request's `Authorization` header shows which one was used.
- `container.test.ts` runs `scripts/` as subprocesses against synthetic auth files and dotenv files in temporary directories and a fake `docker` on `PATH`. The fake `docker` never runs the script a container would, so the in-container probes (`container-skill-probe.sh`, `container-backend-probe.sh`) are run directly with a fake `opencode` and `wget`. It needs Bash, POSIX `sh`, GNU `timeout`, `base64` and Bun, and never real Docker, credentials or paid calls. Keep each safeguard (sandbox checks, seed refusal, container stop and unconfirmed stop, seed ownership, stale-work refusal, the probes' failure cases) tested there once.
- Package tests build and pack a staged copy, then load the package through its public exports in a separate Node process with only runtime dependencies. They need Git, Bun, npm, tar and Node, an installed dependency tree, and no credentials or network. Check SDK absence from the installed package's resolution context.
- Keep subprocess test environments synthetic: pass PATH, a temporary HOME and explicitly supplied test settings; never spread `process.env`. Tests of auth-file fallback must redirect the store to a temporary directory. Other tests use valid synthetic `OPENCODE_AUTH_CONTENT`, so a failed assertion cannot fall through to the real store.
